# OmniTurbo v0.1.3 — Subscriber Failure Isolation

OmniTurbo v0.1.3 corrects a synchronous post-commit subscriber notification defect in the `@r146023/omniturbo` library.

- A subscriber callback that throws synchronously after a successful write no longer changes the writer's result into an apparent failure or prevents subsequent eligible subscribers from receiving the update.
- Successful committed mutations retain truthful `OmniResult` success semantics and return sanitized `OMNI_SUBSCRIBER_CALLBACK_FAILED` warnings through the existing `issues` field.
- Direct, global, tree and parent subscriptions, protected setters and independent private roots, undo and notified batches retain their tested behavior.
- No new production/runtime dependencies. The change does not add supervision for asynchronous Promise rejections.

## Runtime qualification and release security disclosure

Full tests, TypeScript typecheck, build, fresh packed native-ESM package installation, and package-content checks were qualified on Node 22 and Node 24 during candidate preparation. The production-only `npm audit --omit=dev --audit-level=high` reported **zero vulnerabilities** on both supported Node versions.

**Security notice:** This release uses a **Project Owner-accepted, v0.1.3-only exception** for pre-existing vulnerabilities in OmniTurbo's development/testing dependency graph. The full `npm audit --audit-level=high` was **not passing** at the time the exception was prepared: nine known package entries were reported (four moderate, three high, **two critical**). The full audit remains executed and its failures are not represented as passing.

The exception is constrained to an exact, frozen dependency lockfile and the specifically documented known advisories; any new advisory, different lockfile, additional runtime dependency, non-zero production-only audit, or different package version must fail the automated release security gate. Development-tooling remediation remains separately tracked under OmniTurbo `ASSISTANT-ISSUE-0002`.

The GitHub Release includes downloadable, unmodified npm audit JSON snapshots:
- `SECURITY-AUDIT-FULL.json` — full tooling-inclusive audit, including known findings.
- `SECURITY-AUDIT-PRODUCTION.json` — separate production-only audit.
- `SHA256SUMS` — SHA-256 checksums for the `.tgz` package and both audit reports.

The full security status and exact advisories should be assessed from the attached audit reports at the time of publication rather than assuming the historical count always remains nine.
