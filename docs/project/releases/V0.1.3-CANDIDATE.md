## Proposed release summary

Patch release fixing the handling of **synchronously thrown post-commit subscriber callbacks**. If one direct, global, tree or parent-path subscriber throws after a write was committed, subsequent eligible subscribers still run, and the write returns a truthful successful `OmniResult`. The existing `issues` array contains sanitized `OMNI_SUBSCRIBER_CALLBACK_FAILED` warnings without exposing observer exception text or private write tokens. The same isolation applies to committed undo and notified batch paths.

Direct/tree/global/parent arguments and order, `once`/unsubscribe/throttle semantics, protected-root token isolation and pre-commit privacy/validation remain as specified. Asynchronous Promise rejection supervision is **not** part of this patch.

No public API surface redesign or production runtime dependency was introduced. A Windows-only package-consumer smoke-test launcher correction allows the existing packaged native ESM verification to run under Node 22/24.
